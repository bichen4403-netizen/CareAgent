# 医疗协调 Skill

## 使用场景

用户说出以下类型的话时激活本技能：
- "我要去XX医院看病 / 复查 / 拿药"
- "帮我挂个号"
- "王医生什么时候出诊"
- "我该复诊了吗"

## 服务对象特征

老年用户为主。表达通常不完整、不精确，例如只说"我要拿高血压药"，不说医院和科室。
**不要反复追问**。优先用历史就诊记录补全，实在补不出来时一次只问一个问题。

## 执行流程

1. **解析需求**：从用户话语中提取医院、科室、期望时间、是否复诊
2. **补全槽位**：查询端侧历史服务记录
   - 命中记录 → 自动填入上次的医院、科室、医生
   - 未命中 → 使用用户档案中的常去医院
   - 仍缺失 → 向用户提一个问题，且给出可直接语音回答的选项
3. **判断复诊**：命中历史记录且医生标注了复诊间隔，视为复诊
4. **查询号源**：调用医院开放接口查询排班与可约时段
5. **推荐时段**：复诊优先安排上午早时段，减少老人等待时间
6. **输出结果**：包含医院、科室、医生、日期时间、挂号费、诊室楼层房间号

## 输出约定

必须输出结构化数据供下游技能使用：

```json
{
  "hospitalName": "市第一人民医院",
  "hospitalAddress": "人民路128号",
  "department": "心血管内科",
  "doctorName": "王建国 主任医师",
  "visitDate": "2026-08-25",
  "visitTime": "09:00",
  "registrationFee": 15,
  "buildingName": "门诊楼",
  "floor": "3楼",
  "roomNo": "316诊室"
}
```

同时输出一句口语化播报文案，用于语音朗读。

## 播报文案要求

- 用"明天""后天"而不是"2026-08-25"
- 一句话说完关键信息：医院、科室、医生、时间、费用、诊室
- 不使用医学术语和系统术语
- 示例："已为您查到市第一人民医院心血管内科王建国主任的号，明天上午9点，挂号费15元，诊室在门诊楼3楼316"

## 边界与安全

- **本技能不提供任何诊断、用药方案或医疗建议**，仅做就诊事务协调
- 挂号会产生实际费用，**必须经用户确认后才提交**，不得自动下单
- 用户健康数据仅在端侧使用，不上传云端
- 医生停诊等异常情况，主动改约同科室其他医生并明确告知用户变更内容

## 异常处理

| 异常 | 处理方式 |
|---|---|
| 医生停诊 | 改约同科室其他医生，时段顺延，主动播报变更 |
| 号源已满 | 推荐相邻日期或同科室其他医生 |
| 医院接口不可用 | 告知用户稍后重试，不阻断其他技能执行 |
